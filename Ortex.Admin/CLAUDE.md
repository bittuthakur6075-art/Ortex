# Ortex.Admin (business console)

Repo-wide rules, environments, roles and cross-app mirrors are in the root `CLAUDE.md`. This project **owns the database** for all clients: `supabase/migrations`, `supabase/functions`, `supabase/maintenance` (manual SQL, never run by `db push`).

```bash
npm run dev             # Vite on :5180; no Supabase env -> localStore demo mode
npm run dev:staging
npm run build           # check-env -> production build
npm run build:staging
npm run check:env
npm run provision -- <ref>  # push migrations + deploy every function to a project
npm run check:functions     # Deno 2 type-check of every edge function (CI runs it)
npm run icons               # regenerate icons from public/icons/app-icon-1000.png
npm run lint                # oxlint
npm test                    # vitest (pure lib tests)
```

## Architecture

* **Source layout**: `src/pages/` one page per module, plus hub pages; `src/components/{layout,ui,editors,documents,anu}/`; `src/hooks/`; `src/lib/` pure helpers (`pricing.js` GST engine, `analytics/`, `format.js`, `roles.js`, ...); `src/data/store/` (repository facade, `apiStore`, `localStore`, supabase client, sync), `src/data/domain/` (schema, rules, settings defaults, module registry, `whatsNew.js`), `src/data/seed/`; `src/services/` outbound integrations.
* **Data**: every table is `{ id, doc jsonb, created_at, updated_at }`. `data/store/repository.js` uses `apiStore` when Supabase env vars exist, else `localStore`.
* **Auth**: password + emailed OTP (`lib/auth.js`), invite-only. Forgot password on `pages/Login.jsx` runs email -> code -> new password on one ephemeral client, so the route guard never sees the recovery session (mirrors `Ortex.Mobile/src/lib/auth.ts`). Hidden in demo mode.
* **Edge functions**: `supabase/functions/<name>/index.ts`, each deployable alone. Shared code in `_shared/`: `http.ts` (CORS + `json()`), `auth.ts` (`requireStaff(req)`), `gemini.ts` (`generateContent`, `extractText`, `logAiUsage`), `images.ts` (`ownStorageUrl`: only fetch our own storage URLs), `fcm.ts`, `linkedin.ts`, `instagram.ts`, `telecaller.ts`. Import from there, never redefine. Functions called by pg_cron or OAuth callbacks are deployed `--no-verify-jwt` and check their own secret.
* **Hub pages** (tabbed, pattern in `pages/Crm.jsx`): `/crm?tab=leads|enquiries|voice`, `/catalog?tab=products|categories|work`, `/billing?tab=invoices|payments`, `/insights?tab=growth|sales|events`, `/attendance?tab=...`, `/payroll?tab=...`. Embedded pages take `embedded` and swap `PageHeader` for `ActionBar`. A hub is guarded by `HubGuard` (any of its module keys), each tab by its own key. Old single-page routes redirect to the tab and keep router state (`openId`, `openLeadId`, `fromCustomer`, `fromEnquiry`). Pages open a specific record through `state.openId`.

## Database rules worth knowing

* **Audit trail** (0023): `created_by` / `updated_by` are stamped by the `stamp_actor` trigger from `auth.uid()`, never by the client. `audit_log` is append-only (no write policy) with a per-key `{from, to}` diff. `staff_directory` is the safe view for resolving an actor uuid (no email, modules or active flag). Not retroactive: a NULL `created_by` renders as "Not recorded"; a NULL actor inside a log entry means the service role ("Automation"). UI: `repo.history()` -> `hooks/useRecordHistory.js` -> `components/ui/RecordActivity.jsx`; per person, `repo.actorHistory()` on `/users/:id`.
* **Quotation delete is admin-only in the database** (0022). Numbers come from `sequences` via the atomic `next_sequence` RPC, so a delete leaves a gap.
* **Public catalogue boundary** (0020): the website reads `products_public` / `categories_public`, which rebuild the doc key by key as an allow-list. A new website-facing field means editing the view. Visibility is `doc.showOnWebsite` (absent = visible), separate from `status`.
* **Anu's knowledge base** (0028): `anu_knowledge` is written ONLY by `anu_knowledge_sync` triggers on `products` / `categories` / `work`. The trigger swallows its own errors (it must never block a product save) and bumps `anu_knowledge_version`.
* **Leads become customers** (0029): triggers on `enquiries` and `leads` call `upsert_customer_from()`, matching like `sameCustomer` (email, then national phone digits), filling blanks only, skipping Anu's filler names.
* **Settings**: the `settings` table is admin-only (it holds integration keys); non-admins read the `settings_staff` view (0024). `settings` is `superAdminOnly` in the module registry.
* **Storage buckets**: `product-images`, `avatars` (owner-scoped `<uid>/`), `chat-files` (private, members of the conversation named by the first folder), `voice-recordings` (private, anon insert-only), `social-media`, `app-releases` (public, no list, service-role writes), `attendance-selfies` (private, historical). If uploads fail with "Bucket not found", check the bucket exists: `db push` will not recreate one that was deleted by hand.

## Modules

* **Dashboard** (`pages/Dashboard.jsx`): a page for the next hour. "Needs you today" (overdue invoices, Anu complaints and uncontacted calls, new enquiries, expiring/stale quotations), Performance (7/30/90 vs previous window, change stated in words), Pipeline, Receivables. Every figure is a pure function in `lib/analytics/today.js` (tested); every section gated with `canAccess`. Longer-range analysis is Insights -> Sales (`lib/analytics/sales.js`).
* **Leads and enquiries**: `enquiries` holds web enquiries AND Anu voice captures; Voice calls folds them per conversation with `voiceCallsFrom` (`pages/voice-leads/helpers.js`). `leads` is the pipeline. `lib/advisories.js` (`enquiryAdvisories`, `voiceCallAdvisories`) is the single source of the pre-call advice for BOTH clients: each gap is phrased as the question to ask. Recordings play in the Voice drawer through 1-hour signed URLs (`services/voiceRecordings.js`); a missing object reads "Recording not available", not an error.
* **Quotations and invoices**: full-page editors on `components/editors/DocumentEditorShell.jsx` with `CustomerPicker` and `LivePreview` (the real `DocumentSheet`, scaled). Customer checks in `lib/validateCustomer.js`. Per-rep quotation defaults in `profiles.quotation_defaults` (0027; `lib/quotationDefaults.js`). Local drafts in `lib/quotationDraft.js`. WhatsApp share: `lib/quotationShare.js` + `components/documents/documentPdf.jsx`. Print is `window.print()`, PDF is `html2pdf.js`, A4 with notes pinned by `mt-auto`.
* **Tally XML import** (inbound, invoices only): parses TallyPrime Sales Voucher XML (sample `test/fixtures/tally-sales-invoice.xml`). Imported invoices carry **aggregate totals only, no `lines`**, so `DocumentView` must default defensively, and are stamped `doc.tally.status = "synced"`.
* **Catalogue**: bulk import in `components/editors/ProductImport.jsx` (xlsx/CSV template, "Copy AI prompt", `imageUrls` column, and pictures pasted INTO the sheet, extracted by `lib/xlsxImages.js` from the drawing anchors and uploaded at import time, never at preview). `xlsx` and `fflate` are dynamically imported.
* **AI writer and photo studio** (functions shared by both clients): `ai-writer` is the one "Write with AI" backend (`purpose`, `context`, `mode`, `format`; house rules: Indian English, no dashes, never invent prices/dates/GSTINs/specs). It runs on Gemini's free tier, which may train on prompts, so `context` carries only the record being written. `product-image-studio` edits photos on Cloudflare Workers AI (FLUX.2 klein, secrets `CLOUDFLARE_ACCOUNT_ID` + `CLOUDFLARE_API_TOKEN`), always into a NEW object under `product-images/products/ai/`, and both clients show before/after for a person to accept, because a changed logo on a made-to-order product photo is a misrepresentation.
* **Social** (`pages/Social.jsx`, `pages/social/`; functions `social-researcher` -> `social-creative` -> `social-publish` -> `social-accounts`; guides `docs/guides/META_SETUP.md`, `LINKEDIN_SETUP.md`): idea -> draft -> review -> admin approves -> publish now or at `scheduledFor`. Approval is admin-only in the database. **A post can never go out twice**: `social-publish` claims the row (conditional update to `publishing`) before calling the platform, records each platform's result, skips platforms with an id on retry, and turns a stale `publishing` into `failed` rather than resending. Instagram: JPEG only, 4:5 to 1.91:1, 2,200 caption chars, 30 hashtags (checked in `lib/socialImage.js` and in the function). Tokens live in `social_connections` (RLS on, no policy: service role only); LinkedIn and Instagram tokens are renewed by the sweep. Sweep auth is `x-social-secret`. Graph API default v25.0.
* **AI Telecaller** (`/telecaller`): `telecaller_jobs` + `telecaller_calls`; engine in `_shared/telecaller.ts`; functions `telecaller-dial`, `telecaller-engine` (pg_cron), `telecaller-webhook`. Providers `simulate` (default) and `vapi`. `settings.telecaller` is mirrored by `DEFAULT_TELECALLER` in the shared module: keep them in step. Setup: `docs/guides/TELECALLER_SETUP.md`.
* **Team chat** (`/chat`, module `chat` = always; migration **0045**, function **`anu-chat`**): WhatsApp-style direct chats, groups and one private **Anu thread** per person. Tables `chat_conversations` / `chat_members` / `chat_messages` are relational (not `{ id, doc }`) and have **SELECT policies only, for members only**: every write is a security-definer RPC (`chat_send` with a client-generated id so a retry is idempotent, `chat_open_direct`, `chat_create_group`, `chat_add_members` / `chat_remove_member` / `chat_rename` for the group owner, `chat_leave` which hands ownership on, `chat_edit` within 15 min, `chat_delete` for everyone, `chat_mark_read`, `chat_set_muted`, `chat_inbox`, `chat_people`). **Admins cannot read other people's chats.** Files go to the private `chat-files` bucket under `<conversation id>/`, read through signed URLs. Code: `services/chat.js` (RPCs, uploads, ONE realtime channel `ortex-chat`), `hooks/useChat.js` (shared inbox store + `useChatThread` with optimistic sends), `hooks/useChatPresence.js` (online and typing over Realtime presence: user ids only, never text), `lib/chat.js` (pure, `chat.test.js`), `pages/Chat.jsx` + `pages/chat/`, `components/chat/ChatNotifier.jsx` (toast / desktop alert / tab-title count, mounted in `AdminLayout`). **`apiStore`'s shared channel ignores `chat_*` tables**, or every message would re-fetch every collection on the page. **Anu in chat** is read-only: `components/chat/useAssistantChat.js` saves the question, calls `anu-chat` (staff-gated Gemini proxy; returns parts verbatim, thought signatures included), runs each functionCall in the browser through `components/anu/readTools.js` (shared with voice Anu), loops up to 5 rounds and saves the answer as kind `assistant` with its record cards in `meta`. Her own tools are `console_help` (the `HELP` articles in `components/chat/assistant.js`: **keep them in step with real button labels**) and `whats_new`.
* **Anu for staff** (`components/anu/`, header button or Ctrl/Cmd+J): a 400px docked panel; `useAnuController` lives in `AdminLayout` so a conversation survives route changes. `useAnuSession.js` speaks Gemini Live with an `anu-staff-token` token and runs every tool through `repo` under the user's own session with `canAccess` checked first; the READ tools live in `readTools.js`, shared with Anu in Team chat. Writes (`set_enquiry_status`, `start_quotation`) need an on-screen Confirm. Pure answers are `lib/anu.js`, a port of `Ortex.Mobile/src/domain/anu.ts`: edit both.
* **Users** (`/users`, admins): creation via `admin-create-user`, everything after via `admin-manage-user` (`services/users.js`). Deactivating sets `profiles.active = false` AND bans the auth user. The server refuses to disable or delete the caller's own account. Role permissions for accounts/sales/staff are edited by the Super Admin on Users -> Roles & permissions.
* **Profile** (`/profile`): name, password (`PasswordCard`), photo (`AvatarUploader`, 256px crop to the `avatars` bucket; `refreshProfile()` re-reads everywhere).

## Attendance, leave and payroll

Plans: `docs/pm/ATTENDANCE_LEAVE_PLAN.md`, `docs/pm/PAYROLL_PLAN.md`.

* **Attendance is marked ONLY in the phone app** (no clock-in on the web). Punches go through the security-definer RPC `attendance_punch()`; `attendance_punches` has no write policy.
* **Proof of presence is a rotating QR code** (0043, replacing the selfie + geofence of 0033). `attendance_qr` holds one token per station (a `work_sites` row); the table has no RLS policy, so the token reaches a browser only through `attendance_qr_show()`, never over realtime. The code rotates every `qrRotateSec` (30s), is burned on a successful punch (the next is issued in the same transaction), and is shown only to the Super Admin or an admin with the `attendance-qr` grant (`attendance_qr_issuer()`, not `has_module_access()`). Refusals: `wrong_code`, `used_code`, `expired_code`. **Field staff (Sales) punch with no code** and the row is flagged `no_code` for review. There is no offline punch queue (a 30s code cannot be replayed later).
* **Token generation uses `gen_random_uuid()`, never pgcrypto** (0044): these functions pin `search_path = public` and `gen_random_bytes` lives in `extensions`. `services/attendanceQr.js` surfaces the server's own error text as `detail`.
* **One check-in and one check-out a day** (0042; refusal `day_done`); anything else is a correction.
* **Day statuses** (0034): `attendance_days` (P, HD, A, OD, WO, H, MP, L, LOP) is computed, never typed. `holidays`, `regularisations` (corrections, decided by an admin, never on one's own), `attendance_months` (the payroll lock; only the Super Admin unlocks, with a reason).
* **Leave** (0036): `leave_types` (EL, CL, SL, CO, LOP), `leave_ledger` (every balance change is a row), `leave_requests` (applied on either client, decided by an admin, days counted by the server). pg_cron accrues/lapses. 0038 adds comp-off expiry and push to approvers.
* **Pre-0043 rows** keep their selfie and coordinates; the history screens still draw them, and `attendance-housekeeping` deletes selfies past the retention setting.
* Console: `/attendance` tabs Today, Register, Corrections, My attendance, Leave, QR code (`pages/attendance/QrCodeDisplay.jsx`, full-screen display for the gate), Settings (Super Admin). `lib/attendance.js` is GENERATED from `Ortex.Mobile/src/domain/attendance.ts`: edit the TS side.
* **Payroll** (0040, modelled on Zoho Payroll India): `/payroll` tabs Dashboard, Pay runs, Employees, Approvals, Loans, Reports, Settings (Super Admin). Access is `is_payroll()`, never `is_admin()`. PAN and bank account are encrypted with a Vault key; the table keeps only the last four digits. Pay runs go draft -> pending approval -> approved -> paid; a payslip is visible to its employee only once paid. Not yet run end to end with real salaries.

## Design system (Keystone / Metronic port)

Tokens in `src/index.css` (Tailwind v4 `@theme` over HSL vars); kit in `components/ui/Ui.jsx`.

* **Flat surfaces**: every `--shadow-*` token is `none` except the two overlay tokens (1px ring). Never add an in-page `shadow-*`.
* **Semantic utilities only** (`bg-card`, `text-muted-foreground`, `text-warning-text`, `bg-success/12`, `squircle`, ...). Never raw Tailwind hues or hex.
* **Buttons: exactly three sizes** via `size` on `Button`: `sm` 30px, `md` 40px (default), `lg` 50px; `icon` for square. Never override height, text, padding or radius from a page. Every button carries `squircle`.
* **Tables**: `mt-head` on `<thead>` and `mt-body` on `<tbody>`, always both. Those rules are unlayered CSS and beat Tailwind utilities, so padding/weight classes on a `<th>` do nothing. Horizontal rules only.
* **Form controls**: one `CONTROL` class backs `Input`, `Textarea`, `Select` (45px). `Select` is a portal-rendered listbox that still takes `<option>` children and calls `onChange({ target: { value } })`.
* **List-page toolbars**: `ChipGroup` filters left; right-pinned `SearchInput` then `ToolbarButton` / `ExportButton` (both 45px from `TOOLBAR_SHAPE`). Title and primary create button live in the table's `CardHeader`. Reference: `pages/Enquiries.jsx`.
* `Tabs` is the hub-level underline switch; `PillTabs` is for a sub-tab row on the canvas.
* Icons: Iconsax via `components/ui/Icons.jsx`, `Bulk` variant everywhere except the header (`Linear`).
* App icons: `public/icons/app-icon-1000.png` is the master; `npm run icons` generates the rest (never hand-edit). No service worker yet.
