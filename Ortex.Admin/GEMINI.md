# GEMINI.md — Ortex.Admin (Business Operations Console)

This project is the core operations ERP/CRM and **owns the database**: `supabase/migrations/` and `supabase/functions/`.
Cross-repo rules and invariants are defined in the root `GEMINI.md`.

## 2. Architecture & Data Layer

* **Layout**:
  * `src/pages/`: Module and hub pages (`/crm`, `/quotations`, `/billing`, `/attendance`, `/control`, etc.).
  * `src/components/`: Split into `layout/`, `ui/` (`Ui.jsx` design kit), `editors/`, `documents/` (A4 prints/PDFs), `anu/`.
  * `src/data/store/`: Facade `repository.js` dispatches to `apiStore.js` (live Supabase) or `localStore.js` (browser fallback).
  * `src/data/domain/`: `schema.js`, business rules, `settingsDefaults.js`, `modules.js`, `whatsNew.js`.
  * `src/services/`: Outbound integrations (voice recordings, users, push, telecaller).
* **Supabase vs Local Demo Invariant**:
  * `seedDemo()` and `apiStore.clearAll()` throw an error on the live database to prevent accidental data destruction.
  * Invoices and payments calculate settlement status directly in PostgreSQL (Migration 0066). The client never writes `amountPaid` or `paidAt` directly on Supabase.
* **Authentication**:
  * Email + password (`src/lib/auth.js`). Sign-up is invite-only; password recovery runs on an ephemeral client so route guards never see recovery sessions.

## 3. Database Rules & Core Systems

1. **Audit Logging (Migration 0023)**:
   - `created_by` / `updated_by` are stamped via the `stamp_actor` trigger from `auth.uid()`.
   - `audit_log` is append-only. Reading is partitioned per module via `audit_can_read(table)`.
2. **Number Sequences**:
   - Quotation (`Q-`), invoice (`INV-`), payment (`PAY-`), and credit notes acquire numbers via the atomic RPC `next_sequence(series, company)`. Deleting records leaves sequential gaps by design.
3. **Multi-Company Architecture (Migrations 0075–0078)**:
   - Three corporate entities: **Ortex**, **Aman**, **Nidhi**.
   - Tables with `company_id`: `enquiries`, `leads`, `customers`, `quotations`, `invoices`, `payments`.
   - `data/store/company.js` tracks selected company context ("all" or company UUID).
   - Documents dynamically bind letterhead, logo, GSTIN, bank accounts, and terms via `settingsFor(global, companies.doc)`.
4. **Storage Buckets**:
   - Public by URL, list restricted: `product-images`, `avatars`, `social-media`, `company-logos` (Migration 0078).
   - Private, authenticated/signed URL access only: `chat-files`, `voice-recordings`, `attendance-selfies`.

## 4. Key Functional Modules

### 4.1. Quotations, Invoices & A4 PDFs
* **Quotation Editor** (`src/pages/Quotations.jsx`, V3 minimal builder):
  * Dynamic GST tax bases per rate, MOQ auto-lift, and line item search.
  * Validation via `src/lib/validateDocument.js` (blocks save on errors, warns on missing metadata).
* **Tax Invoices** (`src/pages/Invoices.jsx`):
  * Compliant with GST Rule 46 (mandatory "Tax Invoice" title, reverse charge indicator, authorized signatory block).
* **Document Printing & PDFs**:
  * **Strict A4 Invariant**: All PDFs (quotes, invoices, payslips, receipts) must render as a single A4 page generated by `buildSheetPdf` in `src/components/documents/documentPdf.jsx` via `html2pdf.js`. Local overrides of page sizes are forbidden and fail `lib/a4Only.test.js`.

### 4.2. In-Browser OCR Payment Reader (`src/pages/invoices/RecordPaymentModal.jsx`)
* Reads screenshots from PhonePe, Google Pay, Paytm, BHIM, and bank NEFT/RTGS receipts in the browser via Tesseract.js (LSTM OCR). Zero server upload, zero LLM dependency.
* **Image Preprocessing**: `evenPolarity` inverts dark mode and dark banners; Otsu thresholding normalizes lighting.
* **Rupee Symbol Discrimination (`looksLikeRupee`)**: Inspects upper-half horizontal bars to prevent the ₹ symbol from being misread as digits (3, 7, 2, or 8).
* **Direction Detection (`paymentDirection`)**: Compares counterparty details against the company's accounts and `company.paymentAliases` to identify inflows (+) vs payouts (-).

### 4.3. Manual TallyPrime Import (`src/pages/billing/TallyImport.jsx`)
* Inbound sync from TallyPrime via manual Day Book and List of Accounts XML export.
* Matches records by Tally GUID; updates rows only if `ALTERID` is incremented.
* Automatically links incoming receipts to open invoices via Tally's `Agst Ref` allocation.

### 4.4. HRMS: Attendance, Leave & Simplified Payroll
* **Attendance System**:
  * Attendance is clocked **exclusively** on `Ortex.Mobile` by scanning the gate kiosk's rotating 30-second QR code (`src/pages/attendance/QrCodeDisplay.jsx`).
  * Check-in window is constrained to 08:30–21:00 IST. Unclosed days default to absent (`no_checkout`) at midnight.
  * Punches with `no_code`, `own_code`, or `other_site` are flagged for manager regularisation.
* **Leave Management**:
  * Tracks EL, CL, SL, CO, and LOP via `leave_ledger` and `leave_balances`.
* **Simplified Payroll (Migration 0077, `src/lib/payroll.js`)**:
  * **No statutory deductions** (PF, ESI, TDS, LWF, or claims).
  * Supports Monthly Salaried (`salary * payableDays / basisDays`) and Daily Wage (`daysWorked * dailyRate`).
  * Strict **1x Overtime**: Hourly rate calculated from daily rate divided by shift hours.
  * Advance recoveries deducted across pay runs until cleared. Month must be locked before submitting runs.

### 4.5. Team Chat & Deterministic Anu Bot
* WhatsApp-style messaging in `src/pages/Chat.jsx` backed by `chat_conversations` and `chat_messages` using security-definer RPCs.
* **Zero-LLM Anu Engine**:
  * `src/lib/anuIntent.js` and `anuReply.js` parse Hinglish/English queries using deterministic pattern matching.
  * Executes read tools against database RPCs to provide fast, hallucination-free answers.

## 5. Deno Edge Functions (`supabase/functions/`)

Shared utilities live in `supabase/functions/_shared/`:
* `http.ts`: CORS headers and JSON formatting.
* `auth.ts`: Session extraction via `requireStaff(req)`.
* `guard.ts`: Constant-time secret comparison and rate limiting via `rate_limit_hit()`.
* `fcm.ts`: FCM v1 HTTP protocol delivery.
* **Deployment Flags**:
  * Functions called via pg_cron or webhooks must be deployed with `--no-verify-jwt`:
    `push-notify`, `indiamart-lead`, `marketing-sync`, `orty-live-token`, `product-copywriter`.
  * All other functions must maintain JWT verification enabled.

## 6. Design System Rules (Keystone / Metronic Port)

* **Flat Surfaces**: All CSS box shadows are disabled (`none`), except for modal overlay rings.
* **Semantic Tokens**: Use `bg-card`, `text-muted-foreground`, `bg-success/12`, `squircle`. Never use raw hex colors or arbitrary Tailwind palette hues in JSX.
* **Button Sizing**: Strict adherence to 3 sizes: `sm` (30px), `md` (40px, default), `lg` (50px). All buttons must carry `squircle`.
* **Tables**: Use `mt-head` / `mt-body` (or `v2-head` / `v2-body` for CRM/Quotes).
