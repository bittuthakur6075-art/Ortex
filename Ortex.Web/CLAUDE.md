# Ortex.Web (marketing site)

Repo-wide rules, environments and cross-app mirrors are in the root `CLAUDE.md`.

```bash
npm run dev       # Vite dev server. Talks to the LIVE Supabase project (see root CLAUDE.md)
npm run build     # check-env -> check-meta -> vite build -> SSR build -> prerender into dist/
npm run preview
npm run lint      # oxlint
```

Building needs `.env.production` (same Supabase URL/anon key as the Admin), or it bakes the static demo catalogue. `prerender.mjs` reads the `.env` files itself (a plain node script sees an empty `process.env`) and prints `[live catalogue]` when real data was used; it warns loudly when it fell back. `.env.development` holds the same values and declares `ALLOW_SHARED_SUPABASE=true`, without which `check-env.mjs` refuses.

## Architecture

* **Routing**: `src/App.jsx` (pages lazy-loaded through `lib/lazyWithRetry.js`: a failed chunk retries once, then reloads the page at most once per 30 s, as does `vite:preloadError` in `main.jsx`, so a deploy that replaced the chunks never leaves a blank page). `components/layout/RouteErrorBoundary.jsx` wraps the page Suspense (keyed on the path: "This page didn't load" with Reload and Home) and, silently, the deferred widgets. Route SEO metadata is mirrored in `scripts/routes-meta.mjs` (including `/`); `check-meta.mjs` fails the build if they drift. Every page calls `useDocumentMetadata`.
* **A new route needs**: an entry in `routes-meta.mjs`, and an entry in `PAGE_ACTIVITY` in `lib/tracker.js` (or it logs as "Not found page visit").
* **Layout**: `components/layout/` (Navbar, Footer, ScrollToTop); shared blocks in `components/ui/` (`PageHero`, `PageCTA`, `Section`); Home-only sections in `components/home/`. Icons come only from `components/ui/Icons.jsx` (Iconsax adapter), never from a package directly. The mobile menu and `PhotoLightbox` are real dialogs (focus moved in, trapped and returned, Escape closes, Lenis stopped). The mobile menu flips `visibility` at once on open, because a still-hidden element refuses focus. A fixed bottom bar marks itself `data-anu-avoid="on"` (product page quote bar: the Anu launcher and the cookie notice rise above it) or `data-bottom-bar="on"` (quote wizard bar, already above the launcher: only the cookie notice rises).
* **Data**: no server of its own. `lib/supabaseClient.js` reads the catalogue/work photos and inserts leads. The site reads the `products_public` / `categories_public` views (Admin migration 0020), never the tables, so price, cost, HSN and GST never reach it. The quote wizard and contact form queue to `localStorage` when offline (`lib/leads.js`); an insert that stalls 20 s is aborted and goes to the outbox, `getTrackingIds()` works with storage blocked, and both submit handlers release the button in `finally`, so a lead is never lost to a hung spinner. Only a retryable failure is queued (network, timeout, rate limit `P0429`); a row the database refuses for good (42501, 23514, 23502, 22xxx, PGRST1xx) returns `failed` and the form keeps its input and offers WhatsApp. References are unique in the database (Admin 0079), so a 23505 counts as saved; `flushOutbox` runs one replay at a time. Voice rows go through the `save_voice_lead` RPC (0081; on a database without it, PGRST202, they fall back to a plain insert, one row per save, so no lead is lost) and wait in sessionStorage for at most 2 h; a queued save replaces an older one with the same reference. The database caps an anonymous enquiry at 32 KB (name 200, email 254, phone 40, message 8000 characters; the forms enforce the same `LIMITS`, the quote drops its item list from `message` before passing them) and rate-limits anonymous inserts per IP (0079). Artwork uploads after the enquiry is saved, at `artworkPath()`, which the bucket policy accepts only for a fresh Quote calculator enquiry naming that path; a failed upload asks the buyer to WhatsApp the file. The quote cart holds at most `MAX_QUOTE_LINES` (40) and drops products missing from the catalogue only after a successful live read.
* **Single source of facts**: `constants/business.js` (`STATS`, `TERMS`, `MOQ_TIERS`, `PRODUCT_RANGE`, `spokenPhone`) and `constants/site.js` (`SITE_URL`, `ADDRESS`, contact). About, FAQ, Anu's prompt and `STANDARD_RANGE` all read these; change a fact there, never in a copy.

## Prerender / SEO

* Public site: **https://bizgift.ortexindustries.in** (`SITE_URL`). `index.html` and `public/robots.txt` spell it by hand and the prerender fails if they disagree. `www.ortexindustries.in` is a separate, older site: never point a canonical there.
* `prerender.mjs` renders the **whole page body** into `dist/<route>/index.html` for every static route, live category and product, plus `404.html` and a sitemap (with `lastmod` and images). Product URLs are `/products/:slug/:productSlug` (`productSlugs()` in `lib/catalogCore.js`), so renaming a product in the console changes its URL at the next build.
* `entry-server.jsx` renders with `progressiveChunkSize: Infinity`, and the build fails if a page contains `<!--$?-->`. Otherwise React 19.2 "outlines" large Suspense boundaries (spinner in `<main>`, page hidden after the footer), which causes layout shift and hides content from crawlers.
* **Hydration**: `main.jsx` hydrates only when `#root[data-route]` equals the URL. Live catalogue/work rows are embedded as `<script type="application/json" id="ortex-data">` and read by `lib/preloaded.js` only while `#root[data-route]` matches the current path, so `useCatalog`/`useWork` start from what the HTML was rendered with; after a client-side navigation they start loading and share one live fetch per page load (12 s timeout, then the static lists), and product/category pages never redirect before it settles. A live category slug is always `slugify`d, and `prerender.mjs` escapes every value it writes into the head and refuses an output path outside `dist/`. **Anything that renders differently on server and client breaks hydration**: browser-only UI (Anu, cookie banner) mounts after load+idle in `AppLayout`, and above-the-fold heroes use the CSS `hero-in` class, not Framer `initial` (inline `opacity:0` delays LCP).
* JSON-LD: `index.html` holds one `@graph` (WebSite + Organization/LocalBusiness, whose address must match `ADDRESS`); pages add blocks through `hooks/useJsonLd.js`. **No `Product`/`Offer` markup**: prices are never public and Google rejects a Product without one. FAQ answers stay in the DOM (`hidden`) when collapsed. `RollText` draws glyphs with `::before` so link text is not doubled.
* **A console change is indexable only after a rebuild + upload.**

## Deploy

Static Hostinger (`public/.htaccess`, `docs/DEPLOY_HOSTINGER.md`): no SPA catch-all (real 404s), 301 bare domain -> www, strips trailing slashes, 410s a stale URL, and sends CSP, HSTS and Permissions-Policy (`microphone=(self)`). `public/assets/.htaccess` answers a missing chunk with a bare 404 and caches hashed assets for a year. Upload over the old build and keep old `assets/` for a few days, so open tabs still find their chunks. `vercel.json` (unused) carries the same headers and no catch-all rewrite. **Never delete `public/googled41e542536c1f8f5.html`**: it verifies the Google Search Console property.

## Analytics

`lib/tracker.js` writes each visit to `user_activities` (and a derived row to `event_logs`), read by the console's Insights. **Two tiers** (`lib/consent.js`, event `ortex-consent-change`): without analytics consent (not chosen, or declined) `trackAnonymousView` writes an anonymous page view, `doc.anonymous: true` with no `userId`/`sessionId`, no IP or location lookup, no browser/OS, the referrer's hostname only, the path without its query string, device class only, never firing `automation-engine`; nothing is stored in the browser and enquiries carry ids held in memory for the page load (`getTrackingIds`). With consent it is the full row under a stored visitor id (localStorage) and session id (sessionStorage), with searches and IP location; declining deletes both ids. The page a visitor accepts on is written again in full with `metadata.afterConsent`, which the console leaves out of page views. Insights (`lib/analytics/growth.js` `pageViews` / `anonymousViews`, `pages/automation/visitors.js`) counts anonymous rows as page views only, never as visitors, sessions or places. `/cookies` has Accept/Decline buttons to change the choice; the Cookies and Privacy pages describe both tiers (mirror in Mobile `legal.ts`). `App.jsx` calls **`trackPageView`** per pathname, never `trackActivity`: the label comes from `PAGE_ACTIVITY`; searches go through `trackSearch` (1.5 s settle, 2+ characters, consent only). A 300ms debounce collapses double effects and redirect hops. `isLocalTraffic()` drops localhost/LAN rows unless `VITE_TRACK_LOCAL=true`; `Ortex.Admin/supabase/maintenance/remove-local-traffic.sql` cleans up old ones (never run by `db push`). Geolocation is IP-based and **consent-gated**: ipapi.co, then ipwho.is when its daily cap runs out.

## Anu, the website voice assistant (`components/ui/live-orty/`)

**Visitors meet her as "Alisha"** (owner's decision 2026-10-17): every on-screen, aria and spoken use reads `ASSISTANT_NAME` in `live-orty/shared.js`, and the Privacy and Cookies pages (plus the Mobile `legal.ts` mirror and Ortex.Web.Main's Privacy) say Alisha. The code, file names, database objects (`anu_knowledge`, ...) and the lead source `"Voice assistant (Anu)"` keep "Anu": RLS, `push-notify` and the console's Voice calls match on that source. Staff Anu in the console and phone app is unchanged.

**Ortex.Web.Main runs the same files, copied byte for byte** (`LiveOrty.jsx`, `live-orty/*`, `constants/business.js`, `public/anu-mic-worklet.js`, `public/img/anu.jpg`); its build fails when they differ (`Ortex.Web.Main/scripts/check-anu-mirror.mjs`). Change Anu here, then copy the files there. Keep per-site differences out of these files: they read `QUOTE_PATH` and `CONTACT` from `constants/site.js` and `submitEnquiry` from `lib/leads.js`, which each site defines for itself.

Gemini Live (`gemini-3.8-live`, stable) via `@google/genai`, with a single-use token minted by the `orty-live-token` edge function, which locks it to the model the client sends in `body.model` if that is on `liveLockFor`'s allow-list in `_shared/guard.ts` (else the 3.1 preview, still used by staff Anu and the console's Call agent test call). 3.8 rejects `thinkingConfig`, keeps proactive audio always on, and defaults tools to NON_BLOCKING, so every tool in `tools.js` is `behavior: "BLOCKING"`. The token lasts 12 minutes and is rate-limited per IP to 6 per 10 minutes and 20 a day, and 400 a day for the whole site (`_shared/guard.ts`); signed-in staff with the telecaller module (the console's Call agent test) draw from a separate pool. Past that the widget shows the function's "busy" message. **Bot check (Cloudflare Turnstile), behind a switch**: with `VITE_TURNSTILE_SITE_KEY` set (`TURNSTILE_SITE_KEY` in each site's `constants/site.js`), `live-orty/turnstile.js` loads Cloudflare's script when the widget mounts, solves an invisible challenge in the background and sends the token as `body.turnstile` (waiting at most 3 s, then without one); with the function secret `TURNSTILE_SECRET` set, `orty-live-token` verifies it (`verifyTurnstile` in `_shared/guard.ts`: success and one of our hostnames), answers a refused token "busy", and gives a missing token or an unreachable Cloudflare a stricter 2 per IP per 10 minutes. Without the key or the secret, nothing changes. Staff callers skip it. The CSP allows `challenges.cloudflare.com` for scripts and frames.

* **UI**: one bottom-right widget morphing (shared `layoutId`) between `Launcher`, `CallPanel` (live / error / summary) and `MiniCall`. `AnuAvatar` draws `public/img/anu.jpg` inside a canvas ring driven by `readLevel()` (it breathes, reacts to the caller's voice, turns red on error), so the caller can see the line is open. The photo is optional: on error it falls back to `Orb`. **No mute button** (owner's decision): a muted line looks dropped, so the mic stays open for the whole call. When a visitor's action changes the widget's shape, focus moves to the new shape's `[data-anu-primary]` control (never on an auto-opened call); Escape minimises only if nothing else handled it and no other dialog is open.
* **Knowledge**: general facts are `prompt.js`, built from `constants/business.js` and `constants/site.js` plus hand-written content copied from `FAQ.jsx`, `products.js` and `About.jsx`. **A fact changed on those pages must be changed in the prompt too.** Products are live: `catalogue.js` reads `anu_knowledge` (Admin migration 0028, trigger-maintained, anon-readable, realtime), falling back to the 0020 views + `work`. `watchCatalogue()` follows changes during a call (realtime + a 30s version poll), and each `lookup_product` reply carries `catalogue_changed_during_call`, because the system instruction cannot be rewritten mid-call. A product edited in the console is therefore live on the next call with no deploy.
* **`lookup_product` has three tiers, none a refusal**: (1) *listed*, the real product; (2) *standard*, an everyday product in `STANDARD_RANGE` that the console has not been filled in with yet (mirror of the prompt's "WHAT ORTEX MAKES": keep them in step); (3) *custom*, answered with material families, customisation methods, an `ask` list and `closest_we_make`. `classifyItem()` decides `custom`, and only tier 3 becomes "Custom item (not in catalogue)".
* **Matching rules** (each fixed a real mis-answer): products need a hit on name/category/material, not description; `STANDARD_RANGE` matches on the `KINDS` phrase (and a singularised query), not bag-of-words; add-ons come from `KIND_AFFINITY` keyed on what the product IS, with category `AFFINITY` only as fallback (console categories are unreliable). `read()` strips marketplace junk from names (`NAME_NOISE`) because she reads them aloud. A missing material is inferred from the name (confirmed) or the description (unconfirmed: she says the team will confirm); `FITTING_WORDS` stops "metal hooks" making a product metal; a set is always unconfirmed. `moqOf()` treats a minimum of 1 as "not set".
* **The page, not the model, owns the rules of a call**: every `capture_lead` is **merged over what the call already captured** (`callLeadRef`: blanks fall back, sent values win, a sent `items` list replaces ours), then validated by `validateLead` in `leads.js` (real name, 10-digit mobile, numeric quantity per item incl. lakh/crore, timeline, city), and answered with `missing` + a `next` instruction naming the actual product or field. Without the merge, a partial payload failed and she re-asked for details she already had. A resumed call merges over the lead in memory (`priorLeadRef`), and a re-save that changes none of the five details keeps an earlier confirmation. `confirmed=true` counts only when the save before it already held the same complete details (so a read-back happened in between); 3.8 otherwise confirms without reading anything back. Every tool reply's `next` ends with a reminder to answer in the customer's language (`SAY_IT_IN_THEIR_LANGUAGE`), because the prompt's Hindi examples outweighed its switch rule. `parseQuantity` also reads spoken English/Hindi number words and adds compound ones part by part ("teen hazaar paanch sau" = 3500, "1 lakh 50 thousand" = 150000, "pandrah sau" = 1500). Every `capture_lead` updates the call's single enquiry row through `save_voice_lead` (Admin 0081): one reference per conversation, kept in call memory so a resumed call within 2 h updates the same row; a different WhatsApp number, a lead staff have picked up, or one over 2 h old starts a new row. Saves run in order. `end_call` with reason `completed` is refused once (`MAX_END_REFUSALS`) while details are missing; an accepted one hangs up only after her goodbye has both arrived (`turnComplete`) and finished playing, with a 10 s backstop (`END_GRACE_MS`). The "Your details" checklist renders the same validated state.
* **Recording**: `recording.js` mixes both voices into one Opus file and, only when the call produced a lead, uploads it to the private `voice-recordings` bucket (Admin migration 0025). Each lead row carries `doc.call = { id, recording, recordings, confirmed, complete }` (`recordings` lists a resumed call's earlier files). The upload waits for the first lead save and retries once after 2 s if the bucket policy refuses it. The Privacy Policy discloses the recording and Gemini processing, and Anu says in her opener (cold and resumed, `prompt.js`) that the call is recorded.
* **Call behaviour**: memory in sessionStorage (2h cap), loaded into the hook at every `start()` so a reload never overwrites it. **Silence watch**: the Live model never speaks unprompted, so after 12 s with nobody talking (`IDLE_NUDGE_MS`; while the browser blocks her audio no mic audio is sent or recorded, and a call still blocked after 20 s closes quietly) the page sends a hidden turn asking her to re-ask in simpler words, then one telling her to close politely with `customer_busy`, then hangs up itself. A socket closed abnormally in the first seconds with no lead shows the error face, not a 00:00 summary. The call auto-opens 5s after load **once per browser session** (`ortex_anu_autocall`), never for `navigator.webdriver` or a bot-like user agent. `start()` asks for the mic before minting the token, so a refused or ignored prompt costs no token; after 4 s it shows "Allow the microphone", and gives up at 45 s. Minting and connecting each time out after 20 s, and a start-generation counter lets a new `start()` take over from an abandoned one. A 429 shows the function's own `error` text. A dropped call that already saved a lead ends on its summary. A server `goAway` ends the call with the normal summary (no session resumption; `contextWindowCompression` is on). The mic context is 16 kHz, or the device rate where Firefox refuses that, downsampled in `audio.js`. Audio contexts are created before the first `await` (autoplay); a timer-opened call shows "Turn on sound".
* **Audio pipeline**: the mic is captured by an AudioWorklet (`public/anu-mic-worklet.js`, a static file because the CSP allows worklets only from `'self'`; `ScriptProcessorNode` fallback) and must stay on a **zero-gain sink, never `destination`** (it feeds back as a tone). Tuning: explicit echoCancellation/noiseSuppression/AGC, `START_SENSITIVITY_LOW` + 200ms prefix, 500ms end-of-speech silence, a playback lead that grows on each mid-reply underrun (120 -> 360ms), captions animate opacity only. Dev builds log underruns and reply latency; `window.__anu` reports output state.
